# KKS 编码成果审核

## 目的

对用户提交的电厂 KKS 编码成果（Excel，通常数万行、多专业）做**质量审核**，找出阻断导入的问题，
内部按 P0/P1/P2 分级辅助判断，产出面向使用者的全量 HTML 审核报告 + Excel 问题清单，并给出导入建议。

审核分八个维度，**不能只看编码位数，要按设备命名语义理解**（见维度六）。

## 何时使用

- 用户给出某厂 KKS 编码 xlsx（如「江苏太仓锅炉KKS初版」「8.03-舟山KKS编码燃料专业」），要求"审核/审查/检查编码/有没有问题"。
- 用户要求对比两厂编码数量差异（如"鄂州比我们多很多，差异在哪"）——见维度七。
- 用户要求评估编码可否直接导入系统（达梦8 LOCATIONS 表）——见维度八。

## 八维审核框架（检查项总表）

> 完整逐条说明见 `references/KKS编码审核标准检查清单.md`。

**一、文件与结构层（先保证"读对了"）**
1. 多 Sheet 定位主表（导出表/草稿表≠主表，防重复计数）
2. 表头/数据起始行定位（副标题行可能导致整列错位）
3. 关键列动态定位（按表头名定 KKS码/父级/名称/类型列，非固定索引）

**二、KKS 语法/格式合法性**
4. 字符集合规（仅 `[A-Z0-9]` + 分隔符 `-`；`~`/`/` 国标未定义判非法；查小写/中文/全角）
4b. **★分段字符类型（位置感知，P0，必做）**——12位骨架逐段定类型（GB/T 50549-2010 附录 A 图 A.0.1）：`1全厂码G(字母/数字)｜2系统前缀号F0(数字)｜3-5系统分类码F1F2F3(字母)｜6-7系统编号FN(数字)｜8-9设备分类码A1A2(字母)｜10-12设备编号AN(数字)`，**数字段出现字母即错**。
    ⚠️ 只查 `[^A-Z0-9]` 会**漏掉字母O冒充数字0 / 字母I冒充数字1**（它们都在 A-Z 内）。太仓实证：全表"非法字符0"，实则 112 条第10位是字母 O。用 `segment_type_check()`，同前9位兄弟码反证并给建议修正值。
5. 码长合规（设备级 12 位、系统级 5/6/7 位、根 1 位全厂码G；识别变长层级约定；>12 位不立即判错，定性见#17）
6. 结构位取值合规（全厂码 G 须在 GB/T 50549-2010 表 3.3.2 取值内：1-9/A-G/J-R/S-V/Y，自由字母 H/W/X/Z；**KKS 字母表天然排除 I/O**，出现即 P0）

**三、唯一性（主键）**
7. 重复 KKS 码（二分：位置后缀丢失=可机械修复 / 异设备真碰撞=须人工重编）

**四、层级/树结构完整性**
8. 父级参照完整性（孤儿检测）
9. 子码前缀一致性（⚠️变长约定下不用"前N位=父级"推导，须父级列+前缀两条同判）
10. 自引用/环检测
11. 父级长度约束（父码长应<子码）
12. 根节点哨兵（根父级=-1/空）

**五、国标版本迁移一致性（10版→20版，已降级为 P2 历史提示）**
13. 前缀迁移规则（50/60/L0→05/06/61，含 J0→61）——国标体系下 G=5/6/L/J 本身合法，仅历史提示
14. 字母重分配（系统/设备类型字母在重分配表内，非随意改；按厂配置 letter_reallocations）
15. 层级重排（版本间层级位置调整，须人核语义未变）
16. 旧码遗留（父级/个别码仍命中旧前缀表 50/60/L0/J0——P2 历史提示，非 P0/P1）

**六、语义层（按设备命名语义，不能只看位数）**
17. 编码深度定性（>12 码须区分：纯 DCS 点号 `-KFxx` / 部件级附加码 `-XXnn`(MA执行器、MM手动、QA模块、BT热电偶) / 电气 A/B/C 三相独立开关）
18. 旧→新码语义一致（借"原KKS对照列"核设备语义未变）

**七、跨厂/范围对比（"向鄂州看齐"类诉求）**
19. 专业覆盖差异（土建/信息/消防等非工艺专业是否纳入）
20. 编码深度差异（设备级/部件级/信号点号层占比定位数量差异来源）
21. 数量差异分解（瀑布：信号点号增量 + 非工艺专业增量 − 共有设备级盈余，闭合校验）

**八、可导入性（达梦8 LOCATIONS）**
22. 码长突破 LOCATIONS 结构（>12 码无法原样套用，须点号扩展表/第5层扩展）
23. 两票/缺陷历史兼容（硬规则：纸质票面已打印，历史 KKS 不可改写 → 映射层+双码共存+冻结历史）

## 命名与完整性校验（用户扩充，必做）

> 结构校验只能抓"码"的问题；以下针对"名 + 完整性 + 数据卫生"的盲区，分两批补充。

### 第一批（名 + 完整性 三盲区，2026-08-03）
24. **命名模糊/歧义（P1）**：名称省略关键限定词致多解，如"1号2号高加3号液位计"应"1号机2号高加……"。检测：名称"X号Y"结构，每数字须紧跟修饰名词；或见 #28 机器抓。
25. **同设备异码 / 同物异名（P1，提示交人核）**：同一物理设备被编了 >1 个 KKS 码（如设计院图 vs 厂内运行系统图两套叫法、录了两次）。

    ⚠️ **方法论铁律（2026-08-05 实测定论）**：KKS 设备名**天然非唯一定位设备**——
    同屏多回路 FC01~FC10、同系统多馈线 51~54、同子系统多设备都共用基础名、只靠编码后缀
    区分；"同名不同码"是常态(非重复)。**纯名称相似度不可靠**：太仓/鄂州实测名称相似度层
    暴到 8千~10万级候选（命中率 88%，按本技能校准铁律属写错的规则）。同理**图号/位置标识也
    非设备身份键**（图号是图纸级，一张图挂数千台设备，同图号≠同设备）。

    ✅ **可靠路径 = 结构身份键（旧编码 1:1）**：迁移语境下每台设备 1:1 对应一个旧码
    （原KKS码/旧版设计编码）。"`同一旧码 → >1 个不同新码`" = 该设备被编了两次 = **真重复**。
    实现 `identity_dup_by_key(cols, rows, key_col='原KKS码')`；鄂州/太仓实测 0 误报（只报真撞码）。
    🔑 **数据治理建议**：KKS 模板须强制带"1:1 设备身份键"（原KKS码/设计院设备编码）列，
    重复检测才可靠；否则"两套来源、各自旧码"的重复在表内无解，只能人工凭图号+位置裁定。

    🧪 **名称语义相似度（实验性 / 仅人工抽检 / 不可作自动判重）**：`semantic_dup_by_name`
    做跨码字符 n-gram 相似度聚簇（同子系统+改写+无 A/B/进/出区分标记），可作"高可疑"人工
    抽检线索，但**必含大量误报**，绝不自动合并/判重。用户示例"皮带机/带式输送机+采样器/采样装置
    +1号机/1号"能被它命中，但同型不同设备也会命中，必须人凭图号/位置证据终裁。
26. **应编未编（P1，规则库驱动）**：父设备按惯例必含可独立标识子部件（隔离点/回路/执行机构）却缺失。检测：`父设备类型→期望子部件`规则库（开关柜/MCC→抽屉/回路/开关；阀门→执行机构MA/位置开关/电磁阀；泵组→前置泵/电机；变压器→高低压侧开关），父存在但下挂子码无任一期望类型 → 提示。规则库需按专业定标（先建通用 starter）。

### 第二批（六条，2026-08-04 补充）
1. **术语不统一 / 同设备两叫法（P1）**：①"电机/电动机/马达""止回阀/止逆阀/逆止门"风格不一 → **C 方案：先不建词典**，仅做同文件内同物异名聚簇（见 #25），全文件术语归一审计暂缓；②一个设备两种叫法=重复数据 → 由 #25 聚簇覆盖。
2. **名称文本卫生 + 语义可解性（P1/P2）**：名称含非常规符号（全角括号/★/%/emoji/控制符）→ P1；名称提取不到任何已知设备名词（对照设备术语词典+KKS设备字母反推都落空）→ P2"语义需人核"（必有误报，只标不杀）。
3. **机组三方一致（P1，原 B 升级）**：`机组列 ↔ 名称中的机组指代 ↔ 全厂码 G` 三方须一致（G 按 GB/T 50549-2010 表 3.3.2：1-9/A-G→机组号，J-R/S-V/Y→公用）；⚠️**公用/自由白名单**（G=J-R/S-V/Y 及 H/W/X/Z 跳过，勿误报）。
4. **OCR 易混字符待核（P1）**：编码含 I/i/L/l/O/o（图片识别易混）。I/i/O/o 基本确定异常（I/O 不在 KKS 字母表、小写非法）→ 硬标；L/l 经典"1 被识为 L"→ 标"疑为数字1"。**只标不自动改**（L 个别约定或合法）。
5. **文本卫生（码 + 名称，P1，附清洗脚本）**：首尾空白、内嵌换行/制表/缩进、全角空格；码与名称列都查。这类几乎 100% 脏数据、无害可修，导入系统/库易错乱 → **标记 + 附带清洗脚本**（trim + 去控制符 + 全角转半角）。
6. **父子名称语义一致性（P1）**：父名标识 token（如 C8B、带炉/线号词）须与子名一致，父"C8B皮带机"、子"C7B皮带机采样器"→ 矛盾。限直接父子一级、同类设备，避免把"系统→子系统"正常重命名误报。

### 仍保留的轻量增强

- D 空/缺名称（""/-/无/None，设必填则 P0）P0/P1

## 格式变体：系统设备树收集表（芒来电厂实证，2026-08-19）

厂方常提交「系统设备树数据收集」类表（非我们编的），格式与 LOCATIONS 扁平表不同：
- 列：机组(文本)｜主系统(文本)｜子系统(文本)｜设备名｜设备KKS｜子设备名｜子设备KKS。
- **层级由 KKS 码前缀推演**（机组2→子系统7→设备9→部件12），父子关系靠"子设备"同行挂在"设备"下，**无显式父级码列**。
- 实测 7 专业 sheet、17878 行，断层集中在「跨子系统」(6224) 与「跨机组」(653)。

**关键诊断（避免误报）**：该类表"断层"多为**建模方式冲突**而非编码错误——厂方按"运行/工艺关联"把子设备挂父设备下（如给煤机的密封风门、发电机的封母），但 KKS 码把子设备编进各自子系统。用码前缀建树时跨子系统子设备无法挂父设备 → 断层。修法是**增加「父级 KKS 码」显式列**，而非改子设备码（改了会破坏 KKS 子系统归口）。

**层级关系五分法**（判定函数 `rel_type(parent, child)`）：
- `DESCENDS`：child.startswith(parent) → 真父子（链接正常）。
- `SAME_SUBSYSTEM`：child 7位前缀 == parent 7位前缀、但设备字母不同 → 同子系统兄弟（软断层，树可在子系统层连上）。
- `CROSS_SUBSYSTEM`：同机组、异 7位子系统 → 断层(P1，多为运营关联)。
- `CROSS_UNIT`：child 机组位 ≠ parent 机组位 → 断层(P0)。**注意**：先对码做 O→0/I→1 归一再判，因 O1/O2/0I 冒充数字会让"跨机组"虚高（芒来 653→归一后 521，132 条是 O/I 假断层）。
- `MISSING`：child 有码、parent 码空 → 缺父节点(P0)。

**审计脚本范式**（已沉淀）：`audit_manglai.py`（全量扫描→JSON）+ `gen_manglai_report.py`（HTML+13 sheet Excel 全量问题清单），位于 `~/WorkBuddy/.../audit_manglai/`。可复制改写适配其他厂同类表。

## 四阶段工作流（固定范式：inspect→probe→check→diag→gen）

用托管 venv：`C:\Users\Matt\.workbuddy\binaries\python\envs\default\Scripts\python.exe`（裸 python 无 openpyxl）。

### 阶段1 inspect（结构审视）
- 列出所有 sheet + 行数；读前几行表头/副标题，确定数据起始行（常 r0表头/r1副标题/r2起）。
- 按表头名定位 KKS码列、父级列、名称列、设备类型列、原KKS列（**勿用固定索引**）。
- **多 sheet 陷阱**：对比各 sheet 行数/内容重叠，确认主表；导出表/草稿表标"非导入源"。

### 阶段2 probe（特征探测）
- 码长分布直方图；非法字符扫描；重复码统计；父级集合 vs 码集合求差（孤儿）。
- 子码前缀一致性（用父级列，非前N位）；新旧码前缀映射（50/60/L0→05/06/61）。
- 记录"干净项"数量（0 非法/0 超长/0 孤儿）用于报告 KPI。

### 阶段3 check（深度校验 + 语义重分类）
- 重复码二分（#7）；父级缺失二分（#8：可挂上级 vs 旧格式未迁）。
- >12 码语义重分类（#17）：`-KF`=信号点号 / `-XXnn`=部件级 / 末位ABC=分相 → 定量。
- 全厂码 G 取值合规统计（#6：G 须在表 3.3.2 取值内）；10 版旧前缀历史提示（#13-16，P2）。

### 阶段4 diag（诊断归因，避免误报）
- 对每类异常**取样本读真实上下文**再定性，不靠规则孤立判：
  - "父级前缀不一致"在变长约定下可能是混合层级**误报**（六安 1417 条澄清）。
  - "缺失码"可能为主表整合编号取代草稿（舟山燃料 Sheet1 起重机）。
  - 超长码须读名称确认是部件级设备还是点号（鄂州 25,808 条订正）。

### 阶段5 gen（生成产物）
- HTML 审核报告（总体结论 + KPI + 八维结果 + 每类问题明细 + 导入建议）。
- Excel 问题清单（概览、全量问题清单、已澄清项、文件结构、规则覆盖和证据）。
- 数字必须源自脚本统计、报告与表格自洽；差异分解须闭合校验。

## 脚本校准经验（跑模板前必读，全部为实测踩坑）

每加一项校验，**先在一个已知底细的样本上跑一遍看命中量级**：命中率 >5% 基本就是规则写错了，不是数据烂。

| 校验 | 曾经的错法 | 后果 | 正确做法 |
|---|---|---|---|
| 列定位 `name` | `find('名称')` 先命中「设备名称（原）」 | 全部名称类校验都在审旧名 | 优先 `设备名称（必填）/新名称`，再回退并排除「原」 |
| 列定位 `kks` | 用 `exclude=('原',…)` 时连「原KKS」列一起排掉 | `old` 列取空，重复码无法二分 | `old` 单独直配 `原KKS/旧KKS`，不套排除 |
| #27 语义可解性 | 用「设备术语词典」判断名称是否可解 | 太仓误报 **3447** 条（"省煤器/水冷壁"不在词典） | **不建词典**（用户已定）。改硬规则：无中文且无字母 / 长度<2 / 纯符号 |
| #27 符号白名单 | 白名单漏中文标点 `，。；：（）""` | 正常名称"…给水和蒸汽部分，…"全被报 | 白名单含中英文标点＋单位符号；只报控制符/替换符/□ |
| #25 同物异码 | 归一名截断 `norm_name(nm)[:12]` 作键 | 太仓 **603** 组误报（"长吹C1/C2/C3"挤进同桶） | 用**完整归一名**精确相等；桶键系统位取前9位。修后 23 组全真 |
| #26 应编未编 | 按名称关键词命中就当父设备 | **36** 条误报（系统节点名含"泵"被当成泵） | 只对**设备级父节点**(`len==DEVICE_CODE_LEN`)判定 |
| #28 机组一致 | 机组映射写成 `05→unit1` | **8156** 条误报 | 国标化后按全厂码 G（1 位）解析：`05` 的 G=0 非法（由 #6 判 P0）；1-9/A-G 映射机组号，J-R/S-V/Y 与 H/W/X/Z 白名单跳过 |
| #28 机组护栏 | 10版残留前缀 `60` 被当成"60号机" | 滁州 7 条误报 | 国标化后 G 只取 1 位（1-9/A-G），`60` 解析为 G=6（6号机）+F0=0；`MAX_UNIT=16` 护栏，确需判定写进 `UNIT_OVERRIDE` |
| #29 OCR | 把大写 `L` 也当易混 | 大量误报（L 是合法 KKS 字母） | 硬异常只 `I/i/O/o`；软提示只小写 `l` |
| #31 父子语义 | token 正则 `[A-Z]\d+` 抓到 A1/A2 位置变体 | 误报 | 收紧为 `[A-Z]\d+[A-Z]`（C8B 式），且只比同字母族 |
| EQUIP_TERMS | 用 `set('a b c')` 但字符串没空格 | split 出单 token，7758 条误报 | 已废弃该词典；如需保留务必检查 split 结果 |
| #25b 名称相似度 | 想靠字符 n-gram 相似度抓"同物异名" | 太仓 4.5万→去数字后1.4万、鄂州 10万+ 候选（含同子系统多设备/同屏多回路/A-B侧真不同设备） | **KKS 名/图号都非唯一**，名称相似度不可作自动判重；降级为实验性仅人工抽检；可靠路径改**旧编码身份键**(`identity_dup_by_key`) |
| #25c 身份键选错列 | 用 `图号/位置标识码` 当设备身份键 | 鄂州 1072 组"撞码"实为"同一张图上的全部设备"(K0201-01 挂 6598 台) | 身份键须是 **1:1 设备码**（原KKS码/旧版设计设备编码），图号是图纸级不可用 |

## 判定分级约定

- **P0（阻断）**：重复码、父级孤儿、自引用、非法字符（含 `~`/`/`）、**分段字符类型违规(4b，如字母O冒充0)**、全厂码 G 取值非法(#6)、空名称(若设必填)。导入前必须修。
- **P1（需改）**：命名歧义(#24)、术语不统一/同物异名(#1/#25)、名称文本卫生(#2/#27)、机组三方一致(#3/#28)、OCR易混字符(#4/#29)、文本卫生(#5/#30)、父子名称语义矛盾(#6/#31)、应编未编(#26)、A 机器抓项、父级指针错填（如舟山燃料 00EAY 父级误指 00EAV）、字母重分配/层级重排(#14/#15)。
- **P2（提示）**：设备类型中文自由文本、命名风格不一(C/E)、编号断号(F)、字母组合(G)、保留原KKS对照、旧版前缀历史提示(#13/#16)。

## 环境约定（中煤项目）

- 目标库 **达梦 DM8**（Oracle 兼容）；客户端 **DBeaver**；脚本整体执行 Alt+X，关自动提交手动 COMMIT/ROLLBACK。
- 生成 SQL 避开 MySQL 专有：`AUTO_INCREMENT`→`IDENTITY(1,1)`；去 `ENGINE=`/`CHARSET=`；内联索引→独立 `CREATE INDEX`/`ALTER TABLE ADD CONSTRAINT UNIQUE`；注释用独立 `COMMENT ON TABLE/COLUMN`；`DATETIME`→`TIMESTAMP`，`DEFAULT CURRENT_TIMESTAMP`→`DEFAULT SYSDATE`；字符串单引号转义 `''`；`NVL()`/`||`。
- **两票硬规则**：纸质票面已打印，历史 KKS 严禁回写/修改；导入用映射层+双码共存+冻结历史。
- openpyxl 在托管 venv（路径见上）；大 xlsx 用 `load_workbook(..., data_only=True)` 读公式值。
